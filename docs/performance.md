# 性能优化与验证

本次优化保留列表排序语义、用户打标、旧模型读取和爬虫限速。训练、预测、清理与爬取使用持久任务队列，在独立进程串行执行。模型操作另有跨进程锁，CLI 与 worker 不会同时修改模型或清理评分。

## 实现

- 数据库：添加 `add_day`，自动回填旧记录；建立日期排序、类型与日期排序、今日统计、评分筛选和反向标签查询索引。按时间范围统计今日数据。列表总数按共享数据版本缓存，分页不重复统计。
- 搜索：评分通过一次 `IN` 查询加载；标签字典迁移到 `/api/tags`，支持 ETag 与私有浏览器缓存。按标签 ID 精确过滤，避免同名类别和演员混入。
- 预测：专用轻量查询只读取 ID、番号和预取的标签；不用总数统计、页面排序、封面 JSON 或日期格式化。采用固定 ID 上界和游标，每批复用编码器，写入时忽略评分冲突。新增影片优先预测，再补偿历史遗漏。
- 特征与训练：CSR float32 特征；训练分区拟合词表，独立验证分区早停，测试分区只做最终评估；五折交叉验证按需开启。新模型、编码器、特征名和评分一起原子发布，失败保留原文件。
- 任务：HTTP 202 提交，状态与进度持久化到数据库；任务去重、队列上限、完成记录清理、重启中断标记。数据库版本使 worker 更新立即使 Web 缓存失效；进程内缓存有容量限制。
- 图片：线程独立的 HTTP Session 复用连接，按 URL 合并并发下载，原图与 480/960px WebP 分离；限制下载大小与缩略图并发；周期性清理磁盘缓存。Nginx 合并缓存未命中请求，使用 X-Accel-Redirect 发送缓存文件。
- 前端：SSR 首次数据请求与登录 cookie 转发，hydrate 复用 payload；首张封面优先加载，其余懒加载；预留图片尺寸。后台任务进度可跨页面恢复；取消过期列表请求。页码跳转使用数字输入，避免为上万页创建上万个 `<option>`；窄屏按钮换行和分页布局防溢出。

## 本机基准（2026-11-02）

macOS Apple Silicon，Python 3.12，SQLite，本地临时数据库。每种查询测量 15 次，1000 条预测读取测量 5 次。下表为中位数；这不是生产环境端到端压测。

| 测试路径 | 数据量 | 原路径 | 优化路径 |
|---|---:|---:|---:|
| 未评分列表排序 SQL（LIMIT 10） | 1 万 | 3.74 ms | 0.018 ms |
| 未评分列表排序 SQL（LIMIT 10） | 10 万 | 57.65 ms | 0.020 ms |
| 50 条搜索结果评分查询 | 1 万 | 3.01 ms / 50 次 SQL | 0.203 ms / 1 次 SQL |
| 50 条搜索结果评分查询 | 10 万 | 2.96 ms / 50 次 SQL | 0.197 ms / 1 次 SQL |
| 1000 条预测数据读取 | 1 万 | 19.60 ms | 3.68 ms |
| 1000 条预测数据读取 | 10 万 | 129.43 ms | 3.87 ms |

排序基准仅比较 `DATE(add_date)` 与索引列 `add_day` 的 SQL，不包含 HTTP、序列化和图片。预测旧路径复现页面查询的 COUNT、排序、标签预取和 JSON 加载，新路径使用专用游标查询。数据为合成记录，未构造真实业务的标签分布。两种路径均可使用新增的其他索引，结果不等于任意生产数据上的固定加速倍数。新排序查询计划命中 `item_type_day_sort`，未使用临时排序 B-tree。

1000 × 10000 维、每行约 20 个非零标签的矩阵：原 float64 稠密矩阵占 80,000,000 字节，CSR float32 占 163,836 字节。这里比较的是单个矩阵存储，未计模型、Python 对象、数值列和编码过程的峰值内存。

另用临时数据库启动 Bottle、Nuxt 与真实 worker：训练提交约 3 ms，训练期间列表请求最大约 5 ms（小型合成训练集）。验证了登录后 HTML 包含数据、未登录请求重定向、另一浏览器不会继承登录、WebP 缩略图代理，以及训练和重新推荐任务完成。

## 复现

```bash
pip install -r requirements.txt
python -m pytest -q
python scripts/benchmark_performance.py --sizes 10000 100000
npm ci --prefix frontend
npm run build --prefix frontend
python scripts/smoke_test.py

# 浏览器回归：先安装 Chromium，或用 PLAYWRIGHT_CHANNEL=chrome 选择现有 Chrome
(cd frontend && npx playwright install chromium)
python scripts/smoke_test.py --browser
```

测试与基准只使用临时数据目录，不读取或修改业务库、登录密钥和 115 凭证。浏览器测试覆盖登录、SSR hydration 不重复请求、图片尺寸、放大、任务进度和移动端布局。GitHub Actions 运行后端测试、Nuxt 构建与 Chromium 回归。

本机未运行 Docker 镜像或真实 MySQL 实例，Docker/Nginx 的实际容器行为与 MySQL 性能仍需在对应环境验证；上述数据库基准只针对 SQLite。115 接口通过已有 mock 测试验证，没有使用真实账号发起外部下载。
